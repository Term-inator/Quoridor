# 领域文档

本文说明工程技能在探索代码库时应如何使用本仓库的领域文档。

## 探索前读取

- 根目录的 `CONTEXT.md`；或
- 如果根目录存在 `CONTEXT-MAP.md`，按其中的指引读取与当前工作相关的各个 `CONTEXT.md`
- `docs/adr/` 中与当前工作相关的 ADR

如果这些文件不存在，静默继续，不要把缺失本身当成问题，也不要提前建议创建。`/domain-modeling` 等技能会在术语或决策真正确定后按需创建它们。

## 文件结构

本仓库采用 single-context 布局：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用词汇表中的术语

当输出中出现领域概念时，包括 issue 标题、重构建议、假设和测试名称，应采用 `CONTEXT.md` 定义的术语，不要漂移到词汇表明确排除的同义词。

如果所需概念尚未出现在词汇表中，应先判断是否正在发明项目并未使用的语言；若确实存在领域建模缺口，则记录下来供 `/domain-modeling` 处理。

## 标明 ADR 冲突

如果拟议工作与现有 ADR 冲突，应明确指出冲突，不得静默覆盖。例如：

> 与 ADR-0007 冲突，但值得重新讨论，因为……
