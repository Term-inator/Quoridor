# 围墙棋 Pygame 图形界面规格

Status: implemented

## Problem Statement

现有项目已经提供可信的双人围墙棋规则核心、PettingZoo AEC 环境和终端对局，但普通人仍需阅读字符棋盘并输入文本命令，难以直观看清棋子、墙、合法目标和非法放墙原因。研究者也缺少一个适合观察智能体行为的桌面窗口，随机智能体对局会在终端中快速滚过，无法暂停、单步或清楚辨认最近动作。

图形界面必须复用现有规则核心，不能为了鼠标交互复制一套移动、放墙或路径判断。它还要保持强化学习库的基础安装轻量：不需要图形界面的用户不应被迫安装 Pygame，规则核心、PettingZoo 环境和现有 CLI 也不能反向依赖图形模块。

## Solution

在现有包中增加一个支持中文和英语的 Pygame 桌面应用。应用采用原型验证过的“棋盘优先”布局，以固定视角展示棋盘，在右侧提供状态、操作和反馈。人类对局参与者可以直接点击合法目标移动棋子，通过明确的横墙或竖墙模式让鼠标吸附到最近墙锚点；合法与非法预览同时使用颜色、形状和所选语言的文字，非法尝试不会推进回合。

应用直接维护不可变的规则 `Position` 并提交语义动作，不通过 PettingZoo 生命周期驱动桌面对局。首版支持人类对人类、人类对随机智能体和随机智能体对随机智能体；智能体对局提供自动播放、暂停、单步和速度控制。胜负或达到行动上限后显示清晰的结果层，并允许再来一局、返回开始界面或退出。

Pygame 作为名为 `pygame` 的 optional extra 提供，具体使用 pygame-ce 发行实现。基础安装保持可用，图形入口在缺少 extra 时显示可操作的中文安装提示。应用随包分发确定的中文字体资源，以获得跨机器一致的中文字形。

## User Stories

1. 作为人类对局参与者，我希望在桌面窗口中看到围墙棋棋盘，以便无需理解字符渲染也能开始对局。
2. 作为人类对局参与者，我希望从窗口内选择人类对人类模式，以便两个人可以在同一台电脑上轮流行动。
3. 作为人类对局参与者，我希望选择人类对随机智能体模式，以便在没有训练模型时也能独自对局。
4. 作为智能体观察者，我希望选择随机智能体对随机智能体模式，以便观察自动完整对局。
5. 作为人类对局参与者，我希望在人类对随机智能体模式中选择先手或后手，以便体验两个玩家身份。
6. 作为人类对局参与者，我希望先手是默认选择，以便用最少设置开始对局。
7. 作为调试者，我希望可以填写随机种子，以便重现随机智能体的行动序列。
8. 作为普通用户，我希望随机种子可以留空，以便每次获得不同对局而无需理解种子。
9. 作为人类对局参与者，我希望棋盘始终保持 `player_0` 在下方、`player_1` 在上方，以便画面不会在回合之间旋转。
10. 作为人类对局参与者，我希望当前行动方清楚可见，以便知道现在应由谁操作。
11. 作为人类对局参与者，我希望双方剩余墙数始终可见，以便制定策略。
12. 作为对局观察者，我希望已行动手数始终可见，以便了解对局进程。
13. 作为人类对局参与者，我希望棋盘显示 `a–i` 和 `1–9` 坐标，以便界面、CLI 和日志使用同一套人类坐标。
14. 作为人类对局参与者，我希望自己的所有合法棋子目标在回合开始时直接显示，以便不用先点击唯一的一枚己方棋子。
15. 作为人类对局参与者，我希望点击合法目标即可移动，以便操作保持简短直接。
16. 作为人类对局参与者，我希望“移动”“横墙”“竖墙”是明确的操作模式，以便不用猜测鼠标按键或滚轮手势。
17. 作为人类对局参与者，我希望每个人类回合默认回到移动模式，以便降低误放墙的风险。
18. 作为键盘用户，我希望按 `Esc` 可以取消放墙并回到移动模式，以便快速纠正操作意图。
19. 作为人类对局参与者，我希望墙预览吸附到最近的 8×8 墙锚点，以便不必精确点击狭窄缝隙。
20. 作为人类对局参与者，我希望合法墙预览清楚显示为绿色，以便在确认前知道动作可以执行。
21. 作为色觉不同的用户，我希望非法墙除了红色外还有明显叉线，以便反馈不只依赖颜色。
22. 作为人类对局参与者，我希望非法墙仍可点击，以便获得它为什么非法的具体说明。
23. 作为人类对局参与者，我希望墙冲突显示易懂的中文原因，以便理解重叠或交叉限制。
24. 作为人类对局参与者，我希望阻断路径的墙显示易懂的中文原因，以便理解围墙棋的路径保留规则。
25. 作为人类对局参与者，我希望没有剩余墙时获得明确反馈，以便知道为何不能继续放墙。
26. 作为人类对局参与者，我希望非法动作不改变局面、行动方或手数，以便一次误操作不会破坏对局。
27. 作为对局观察者，我希望最近的棋子移动标记起点、连线和终点，以便看清刚发生的动作。
28. 作为对局观察者，我希望最近放置的墙被高亮，以便在复杂棋盘中找到刚发生的变化。
29. 作为对局观察者，我希望状态栏用人类坐标描述最近动作，以便把视觉变化与日志对应起来。
30. 作为智能体观察者，我希望随机智能体不会在同一帧连续行动，以便能够看清每一步。
31. 作为智能体观察者，我希望智能体对局默认自动播放，以便启动后无需逐步点击。
32. 作为智能体观察者，我希望暂停和继续自动播放，以便随时检查局面。
33. 作为智能体调试者，我希望暂停后一次只推进一个智能体动作，以便逐步分析行为。
34. 作为智能体观察者，我希望选择少量清晰的播放速度档位，以便在观察细节和快速完成之间切换。
35. 作为人类对局参与者，我希望随机智能体行动前保留可感知的延迟，以便确认我的动作已经生效。
36. 作为人类对局参与者，我希望包含人类的模式不显示无意义的暂停和单步控件，以便界面只出现当前可用操作。
37. 作为对局参与者，我希望某个玩家身份到达目标行时立即看到胜者，以便清楚知道对局已经结束。
38. 作为对局参与者，我希望达到 512 手仍无胜者时看到“本局未决”，以便不会把环境截断误解为规则上的平局。
39. 作为对局参与者，我希望结果层提供“再来一局”，以便用相同设置迅速重新开始。
40. 作为对局参与者，我希望“再来一局”保留当前模式、玩家身份分配、随机种子和速度设置，以便不用重复配置。
41. 作为用户，我希望结果层提供返回开始界面，以便选择另一种对局模式。
42. 作为用户，我希望结果层提供退出，以便明确结束应用。
43. 作为用户，我希望关闭窗口能够干净退出，以便不会留下挂起进程。
44. 作为小屏幕用户，我希望界面在最小支持尺寸仍保留可操作的棋盘和完整状态摘要，以便侧栏不会被裁切。
45. 作为大屏幕用户，我希望界面等比放大并保持棋盘优先，以便额外空间不会破坏视觉层级。
46. 作为人类对局参与者，我希望棋盘在窗口中占据主要视觉空间，以便下棋而不是调试信息成为首要任务。
47. 作为中文用户，我希望所有窗口文字稳定显示中文，以便不受操作系统字体安装情况影响。
48. 作为基础库用户，我希望安装默认包时不安装 Pygame，以便训练服务器和无图形环境保持轻量。
49. 作为图形界面用户，我希望通过一个明确的 optional extra 安装全部图形依赖，以便不必手工判断发行包。
50. 作为基础库用户，我希望导入规则核心、环境或 CLI 时不会间接导入 Pygame，以便无图形安装正常工作。
51. 作为误运行图形命令的基础库用户，我希望看到中文安装提示，以便知道如何启用界面而不是面对 import traceback。
52. 作为现有 CLI 用户，我希望原来的 `quoridor` 命令继续启动终端界面，以便图形功能不会改变已有入口含义。
53. 作为图形界面用户，我希望独立的 `quoridor-pygame` 命令启动桌面应用，以便两个入口职责清楚。
54. 作为维护者，我希望 Pygame 应用复用唯一的 `Position` 规则实现，以便终端、环境和图形界面不会产生规则漂移。
55. 作为维护者，我希望 Pygame 应用只向规则核心提交语义动作，以便像素坐标和 Pygame 事件不会污染规则模块。
56. 作为维护者，我希望整个 Pygame 应用通过一个主要 seam 验收，以便内部布局、调度和绘制可以重构而不重写大量测试。
57. 作为未来模型 adapter 作者，我希望智能体继续接受 `Position` 并返回语义动作，以便具体模型可以自行封装 observation 和动作编号转换。
58. 作为维护者，我希望智能体提交非法动作时得到确定的判负结果，以便界面行为与 PettingZoo 非法动作语义一致。
59. 作为维护者，我希望智能体实现抛出技术错误时中止对局而不是产生虚假的胜负，以便集成缺陷不会污染比赛结果。
60. 作为维护者，我希望同一开始设置和随机种子产生可重现的随机对局，以便故障可以稳定复现。
61. 作为维护者，我希望字体和许可证文本包含在构建产物中，以便安装后的中文界面可靠且分发合规。
62. 作为维护者，我希望 Linux 上的声明 Python 版本都能运行图形冒烟测试，以便图形 extra 不破坏项目兼容范围。

## Implementation Decisions

- Pygame 功能作为现有 Python 包内的独立图形适配层实现，与规则核心、PettingZoo adapter、ASCII renderer 和 CLI 保持模块化分离。
- 正式功能只有一个新的主要测试 seam：完整的 Pygame 应用接口。它接收用户事件、窗口变化和可控的时间推进，并暴露足以绘制和断言用户可见行为的应用状态。内部可以拆分对局编排、输入解释、布局、绘制和资源加载，但这些内部模块不各自成为调用者必须理解的公开测试 seam。
- Pygame 应用直接拥有当前不可变 `Position`，所有棋子移动和放墙都构造现有语义动作并调用规则核心。它不通过 PettingZoo AEC 生命周期推进桌面对局，也不复制合法动作、墙冲突或路径判断。
- 应用内部状态机至少覆盖开始界面、进行中对局和结果层。进行中状态同时维护玩家身份与对局参与者分配、手数、当前操作模式、最近动作、反馈、智能体计时和播放状态；规则事实仍以 `Position` 为权威。
- 首版提供三种对局配置：人类对人类、人类对随机智能体、随机智能体对随机智能体。人类对随机智能体允许选择人类控制先手或后手的玩家身份。
- 随机智能体复用现有 `choose_action(Position) -> Action` 形状。相同模式、玩家身份分配和基准种子必须重现同一局对局；两个随机智能体各自拥有确定且独立的随机序列。
- 不声明通用对局参与者注册表、插件发现机制或 checkpoint loader。测试可以在应用内部注入确定性的脚本智能体，但该内部 seam 不扩张为公开插件系统。
- 未来训练模型 adapter 负责把 `Position` 转换为训练 observation，并把模型动作编号解码成语义动作。首版不提前提取 observation encoder，因为当前 Pygame 和随机智能体没有该消费者。
- 人类输入先由 Pygame 应用根据当前布局解释为移动目标、墙锚点或界面命令，再跨规则 seam 提交语义动作。任何像素坐标、控件对象或 Pygame event 都不得进入规则核心。
- 棋盘使用固定绝对视角，`player_0` 始终显示在下方、`player_1` 始终显示在上方。PettingZoo 的 canonical 旋转不影响桌面视图。
- 移动模式直接绘制当前行动方全部合法棋子目标。点击非目标区域不推进对局；点击合法目标构造一个棋子移动动作。
- 放墙交互使用明确的横墙和竖墙模式。鼠标位置吸附到最近的 8×8 墙锚点，吸附结果限制在有效锚点网格内；离开棋盘交互区域时不显示墙预览。
- 墙预览是否合法必须由当前 `Position` 判断。合法墙使用绿色预览；非法墙使用红色预览、明显叉线和中文原因，不能只依赖颜色。
- 点击非法墙时调用规则核心获得稳定的 `IllegalActionReason`，保留当前局面、行动方和手数。正式中文反馈沿用原型含义：对局已结束、棋子不能移动到该格、当前行动方已经没有墙、与已有墙重叠或交叉、会堵死至少一方的所有路径。
- 每个人类回合开始后以及每个合法动作完成后，操作模式回到移动。`Esc` 也返回移动模式并清除墙预览。
- 应用保留最近一个合法动作直到下一动作发生。棋子移动使用起点、连线和终点标记；新墙使用高亮；状态栏使用人类坐标描述该动作。
- 视觉方向采用原型确认的方案 A“棋盘优先”。左侧正方形棋盘占主要空间，右侧为紧凑状态与控制栏；不再比较或实现原型方案 B、C。
- 应用使用固定逻辑画布和统一缩放，初始窗口建议为 1280×800，最小支持尺寸为 960×640。缩放保持布局比例和棋盘可操作性，多余空间用留边吸收；最小尺寸使用紧凑侧栏摘要，不能裁掉当前行动方、墙数、手数、模式和反馈。
- 常驻信息包括当前行动方、双方剩余墙数、手数、当前操作模式、最近反馈和棋盘人类坐标。选中控件除颜色外还使用轮廓表达状态。
- 智能体对智能体默认自动播放，默认动作间隔约 500ms，并提供暂停/继续、单步和少量固定速度档位。单步只执行当前一个智能体动作；暂停时经过真实时间不得推进对局。
- 包含人类的对局不显示播放控制。随机智能体在轮到它后仍等待当前配置的可感知延迟，避免与人类动作发生在同一帧。
- 智能体返回规则核心拒绝的非法动作时，该智能体立即判负，结果层区分这是非法动作判负。智能体选择动作时抛出的异常属于技术错误，应用中止对局并显示错误状态，但不得把它记录为围墙棋胜负。
- 正常到达目标行时立即显示胜者。手数达到 512 且无胜者时结束本局并显示“达到行动上限，本局未决”；未决不属于平局或任何玩家身份获胜。
- 结果层覆盖棋盘主要区域并提供再来一局、返回开始界面和退出。再来一局从官方初始局面开始，保留当前进程中的模式、玩家身份分配、种子和速度；应用不把设置写入配置文件。
- 首版键盘辅助只包括取消放墙、智能体播放暂停/继续和单步所需快捷键。完整键盘焦点导航不在本规格内。
- 界面默认使用中文，并在开始页提供中文/English 切换；选择在当前进程、返回开始页和重新开始时保留，但不写入配置文件。全部静态标签、动态反馈、非法原因和历史记录使用键集合一致的中英文文案目录集中维护，不跟随系统 locale，也不引入第三方国际化框架。
- 图形 optional extra 名为 `pygame`，依赖只声明 `pygame-ce>=2.5.8,<3`。代码使用 `pygame` import namespace，不同时支持或回退到上游 pygame 发行包。
- 基础依赖不包含 Pygame。规则核心、PettingZoo adapter、ASCII renderer、包顶层导入和现有 CLI 均不得导入图形模块。
- 保留现有终端命令含义，并新增独立图形命令。图形命令的轻量入口负责捕获缺少 optional extra 的情况并输出包含 extra 安装方式的中文提示；完整应用模块只在依赖可用时加载。
- 原样捆绑 Noto Sans SC Regular 字体和 SIL Open Font License 1.1 文本，使用标准包资源机制加载，不搜索系统字体、不运行时下载、不做首版字体裁剪。字体资源进入基础 wheel，约 8 MB 的体积增加已被接受。
- 字体对象按字号和样式缓存，避免每帧重复加载资源。首版只分发 Regular 字体文件；视觉层级通过字号、颜色及 Pygame 提供的样式表现，不增加第二份字体资源。
- 首版只声称当前 Linux 环境经过项目验证。依赖在 Windows 和 macOS 提供 wheel 不等同于本项目验证，不得在文档中宣称这些平台已经通过测试。
- 不保留原型方案或尚未发布设计的兼容路径。正式实现重新组织已验证行为，不导入原型脚本，也不提供 A/B/C 方案切换。

## Testing Decisions

- 测试通过用户与调用者可观察的行为验证功能，不调用私有布局辅助、绘制步骤、内部计时器、字体缓存或对局状态机实现细节。内部重构不应迫使行为测试改写。
- 现有 `Position` seam 继续独立验证全部围墙棋规则。Pygame 测试只选择少量代表性动作证明应用正确跨过规则 seam，不重复穷举普通移动、跳跃、墙冲突和路径搜索。
- 新功能的主要测试 surface 是完整 Pygame 应用 seam。测试输入真实 Pygame 鼠标、键盘、窗口和退出事件以及显式的 elapsed time，观察应用公开状态、规则状态变化、用户可见反馈和绘制是否成功。
- Pygame 行为测试使用 SDL dummy video/audio driver 和真实 `Surface`，因此不需要打开桌面窗口。测试不比较逐像素黄金截图，也不把精确抗锯齿结果、字体光栅或内部矩形坐标冻结成契约。
- 开始流程测试覆盖三种模式、人类先后手选择、空种子、整数种子、非法种子反馈，以及开始后正确的玩家身份与对局参与者分配。
- 人类移动测试通过真实点击事件验证合法目标提示、目标命中、`Position` 推进、手数增加、行动方切换、最近动作反馈以及自动回到移动模式。
- 放墙测试通过真实鼠标移动和点击事件验证横墙/竖墙选择、最近锚点吸附、合法预览、合法放墙、非法预览、叉线提示、具体中文原因，以及非法点击不改变局面、行动方和手数。
- 反馈测试不只断言颜色值，还验证非法状态具有非颜色标记和文字；坐标、当前行动方、墙数、手数和当前模式在支持尺寸中均存在于可见应用状态。
- 最近动作测试分别覆盖棋子移动与放墙，验证标记持续到下一合法动作并被新动作替换。非法尝试不得清除最后一个合法动作。
- 智能体调度测试使用确定性的脚本智能体和显式时间推进，避免依赖真实睡眠。测试自动播放、默认延迟、多个速度档位、暂停不推进、继续恢复、单步只执行一次，以及包含人类的模式等待人类输入。
- 随机模式测试验证相同种子和设置重现相同行动序列，不同玩家身份拥有独立随机源；随机完整对局必须正常胜出或在 512 手成为未决，不能挂起。
- 异常测试区分三种结果：人类非法尝试被拒绝但对局继续，智能体非法动作导致该智能体判负，智能体实现异常导致技术错误中止且没有虚假胜者。
- 结束流程测试覆盖正常胜利、512 手未决、结果层内容、再来一局保留设置并重置局面、返回开始界面和退出。
- 缩放测试至少覆盖原型验证过的 960×640、1280×800 和 1600×950。测试确认最小尺寸无状态裁切、棋盘保持正方形和可点击、墙锚点命中仍对应相同语义位置，并确认更大窗口绘制无异常。
- 字体资源测试从构建后的包中加载实际 Noto Sans SC 文件，渲染代表性中文并验证获得非空表面；不得依赖开发机系统字体。构建产物同时必须包含 OFL 许可文本。
- 入口测试以子进程运行图形命令：基础安装缺少 extra 时返回明确中文安装提示且无原始 traceback；安装 extra 后可以用 dummy SDL 初始化、处理退出事件并正常返回。
- 依赖隔离测试在没有 pygame-ce 的基础安装中导入包顶层、规则核心、PettingZoo 环境和现有 CLI，确保没有间接图形依赖。现有 CLI 集成测试必须继续通过。
- Linux 上验证 Python 3.11、3.12、3.13 和 3.14 的基础安装与图形 extra。Windows/macOS 没有真实 runner 结果前不列为项目已验证平台。
- 正式基线继续包括完整 pytest、Ruff、格式检查和 mypy。PettingZoo 既有 observation 建议警告不是本功能引入的失败，但新增代码不得增加新的警告或破坏现有 31 项测试。
- 原型是交互和布局的 prior art；现有 CLI 测试是进程入口与完整对局的 prior art；规则测试是语义动作和结构化非法原因的 prior art。正式测试重新表达已确认行为，不导入或逐行复制原型实现。

## Out of Scope

- 训练算法、模型训练、训练结果评估或模型 checkpoint。
- 人类对已训练智能体、训练模型选择界面和通用模型加载协议。
- 提前提取或重新设计 PettingZoo observation encoder、209 动作编码或 action mask。
- 智能体插件注册表、动态发现、第三方扩展协议或复杂依赖注入框架。
- 通过 PettingZoo AEC adapter 驱动桌面对局，或给 PettingZoo 增加 Pygame/RGB-array render mode。
- 修改官方双人规则、增加四人制、可变棋盘或自定义规则。
- 网络对局、远程智能体、账号、匹配、聊天或服务器进程。
- 对局存档、载入、回放、撤销、局面编辑或任意局面导入。
- 动画、音效、图片纹理、粒子效果、自定义主题或素材管线。
- 中英文切换、国际化框架或运行时语言包。
- 完整键盘导航、屏幕阅读器集成、触摸手势或移动设备界面。
- 跨进程保存窗口大小、速度、模式、种子或其他设置。
- 系统字体 fallback、运行时下载字体、字体裁剪或增加多个字重文件。
- 原型方案 B、方案 C、方案切换器或继续扩建原型。
- 逐像素截图回归测试、冻结精确控件坐标或把字体光栅结果当作接口。
- 声称 Windows、macOS、Alpine/musl 或其他未实际运行的平台已经得到项目支持验证。
- PyPI 发布、发行名预留、安装器、桌面快捷方式或发布自动化。
- 为尚未发布的 UI 行为保留向后兼容层。
